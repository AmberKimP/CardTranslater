# 보드게임 카드 한글화 앱 PRD

Nov 3, 2026

## 1. 개요

**한 줄 요약:** 같은 종류의 카드 이미지 여러 장에서, 사용자가 한 번 지정한 영역의 외국어를 모두 뽑아 엑셀로 내보내고, 검수된 번역을 다시 받아 같은 자리에 한글로 덮어 쓴 카드 이미지를 만드는 로컬 앱.

### 풀려는 문제

- 카드는 수십\~수백 장인데 구조는 같다. 한 장씩 텍스트를 입력하고 지우고 한글을 올리는 반복 작업이 가장 오래 걸린다.
- 번역 검수는 사람이 해야 하지만, 검수는 엑셀 표에서 하는 것이 훨씬 빠르다. 용어 통일도 표에서 쉬운다.

### 목표

- 카드 한 종류당 영역 지정은 한 번만 한다.
- 100장 기준, 추출과 초벌 번역은 사람 손을 거치지 않고 10분 안에 끝난다.
- 사람은 엑셀 검수에만 시간을 쓴다.
- 결과 이미지는 바로 인쇄하거나 공유할 수 있는 품질이고, 원본은 절대 덮어쓰지 않는다.

### 범위 밖 (첫 버전)

- 배포용 서비스, 회원, 협업 편집 (내 컴퓨터에서만 돌아간다)
- 카드마다 위치가 다른 텍스트를 자동으로 찾기 (영역은 사용자가 지정)
- 아이콘 그림 자체를 고치거나 새로 그리기 (문장 속 아이콘은 원본 그림을 그대로 다시 배치한다)
- 룰북처럼 긴 문서의 레이아웃 작업

## 2. 작업 흐름

### 게임·프로젝트·그룹 (2026-11-04 결정)

| 단위 | 뜻 | 가진 것 |
| --- | --- | --- |
| **게임** | 번역하는 보드게임 하나(예: ‘Dungeon’) | 용어집(확정 번역), 용어집 검증 파일. 같은 게임의 모든 프로젝트가 함께 쓴다 |
| **프로젝트** | 한 번의 번역 작업. 시작할 때 **새 게임 이름**을 넣거나 **이미 있는 게임**을 골라 만든다 | 그룹들, 진행 상태(추출 중 → 용어집 검증 중 → 용어집 확정 → 번역) |
| **그룹** | 프로젝트 안에서 **같은 카드 형식(영역 템플릿 하나)**을 쓰는 파일 묶음(예: ‘BATTLE·DUNGEON 카드’, ‘아이템 카드’) | 영역 템플릿, 그 그룹의 파일들(파일마다 추출·지우기·한글 넣기 결과) |

- 파일을 넣을 때(텍스트 추출 전) 프로젝트에 이미 있는 그룹 목록(그룹 이름, 파일 수, 영역 수)을 보여 주고, **기존 그룹에 넣을지 새 그룹을 만들지** 고르게 한다. 새 그룹은 영역 지정(2단계)을 해야 추출할 수 있다.
- 텍스트 추출은 그룹 단위로, 그 그룹의 영역 템플릿으로 그룹의 모든 파일에서 한다.
- **카드마다 형식이 달라 공통 영역을 쓸 수 없는 그룹**은 ‘카드마다 영역 지정’으로 만든다(`regions.json`의 `layout: per_card`, 카드별 영역은 `page_regions["<파일>/<쪽>"]`). 영역 지정 창에서 쪽을 넘기며 카드 한 장씩 영역을 그리고, ‘이전 카드 영역 복사’로 비슷한 카드를 빨리 정한다. 영역을 정하지 않은 카드는 추출·지우기·한글 넣기에서 건너뛰고 ‘영역 없음’으로 알린다(정하면 다음 추출 때 읽음). 공통 영역 그룹에서도 특정 카드만 따로 정할 수 있다(그 카드의 `page_regions`가 공통 영역보다 우선).
- 파일 안에 그룹 형식과 다른 쪽(예: Items.pdf 1쪽 규칙 카드)이 있으면 파일마다 **뺄 쪽**을 지정한다(`set-pages`). 뺀 쪽은 추출·용어집·번역·엑셀·지우기·한글 넣기에서 모두 빠진다(다른 형식이면 다른 그룹·템플릿으로 다룬다).
- 지우기(7단계)와 한글 넣기(8단계)도 프로젝트 단위로 모든 그룹·파일에 한다(`erase-project`, `compose-project`). 이미 지운 파일은 건너뛴다. 한글 넣기는 파일마다 검수한 `번역_검수.xlsx`가 있으면 그것을, 없으면 초벌 번역을 쓴다.
- 사용자가 **‘추출 완료’ 명령**을 보내면 그때까지 추출한 모든 그룹·파일의 원문을 모아 용어집 후보를 만들고 **용어집 검증**에 들어간다(4단계). 검증이 끝나 용어집이 확정되면 그 용어집을 기준으로 **전체 텍스트를 번역**한다(5단계).
- 같은 게임의 다음 프로젝트에서는 확정된 용어는 그대로 쓰고 **새로 나온 용어만** 후보로 검증한다.

| 단계 | 사용자가 하는 일 | 앱이 하는 일 | 결과물 |
| --- | --- | --- | --- |
| 0. 프로젝트 만들기 | 새 게임 이름을 넣거나, 이미 있는 게임 목록에서 하나를 고른다. 프로젝트 이름을 정한다 | 게임이 없으면 만들고, 그 게임 아래에 프로젝트를 만든다 | 게임 폴더(용어집), 프로젝트 폴더 |
| 1. 파일 선택·그룹 정하기 | 카드 PDF 또는 이미지(PNG·JPG, 한 장에 한 장 또는 가로 X × 세로 Y 배열)를 고르고, 보여 주는 그룹 목록에서 기존 그룹에 넣을지 새 그룹을 만들지 고른다. 원문 언어를 고른다 | 파일을 그룹에 넣는다. 그룹 안에서 카드 크기가 다른 파일을 경고한다 | 그룹, 카드 목록 |
| 2. 영역 지정 | 첫 카드 위에 사각형을 그리고 이름을 붙인다(예: 제목, 본문). 여러 개 가능 | 좌표를 카드 크기 대비 비율로 저장한다. 다른 카드 몇 장에 같은 영역을 겹쳐 미리 보여 준다 | 영역 템플릿 |
| 3. 텍스트 추출 | 그룹마다 ‘추출 시작’을 누른다. 새로 나온 아이콘에 이름을 붙이거나 제안된 이름을 확인한다. 모든 그룹이 끝나면 **‘추출 완료’**를 보낸다 | 그룹의 영역 템플릿으로 그 그룹 **모든 파일·카드**의 각 영역에서 글자를 읽는다. 아이콘은 `[[coin]]`처럼 이중 대괄호로 감싼 단어로 바꾸고 아이콘 이미지를 백업한다(5.6절). 번역은 하지 않는다 | 원문 목록, 아이콘 사전 |
| 4. 용어집 만들기·검증 | `용어집.xlsx`를 열어 용어별 한국어를 정하고 가져온다 | ‘추출 완료’를 받으면 프로젝트의 모든 그룹 원문을 모아 용어 후보를 뽑고, 게임 용어집의 기존 번역을 채운 뒤 추천 번역을 넣어 내보낸다. 가져온 파일을 검사해 문제가 없으면 게임 용어집을 확정한다(5.3절) | 확정 용어집(게임 단위) |
| 5. 번역·내보내기 | ‘번역 시작’을 누른다 | 용어집이 확정된 뒤에만 시작한다. 프로젝트의 **모든 그룹·파일 원문**을 확정 용어집을 반드시 지키며 초벌 번역한다. `[[단어]]`는 그대로 두고, 용어집을 어긴 칸을 표시한다 | `번역_검수.xlsx` |
| 6. 검수 | 엑셀을 열어 ‘번역’ 열을 고친다. 필요하면 원문 오류도 메모한다 | (앱 밖에서 작업) | 수정된 엑셀 |
| 7. 글자 지우기 | ‘지우기’를 누른다 | 영역의 글자와 아이콘을 지운 카드 이미지를 `cleared/` 폴더로 내보낸다. 번역과 상관없으므로 영역이 정해진 뒤(3단계 이후) 언제든 할 수 있고, 한 번 하면 다시 하지 않는다 | `cleared/`(지운 카드), 전후 비교 |
| 8. 가져오기·한글 넣기 | 수정한 엑셀을 가져온다 | 파일과 용어·아이콘 사용을 검사하고, `cleared/`의 카드 위에 엑셀 ‘번역’ 열의 한글을 넣는다. `[[단어]]` 자리에는 백업한 아이콘 이미지를 그린다. 지우기는 다시 하지 않는다 | `translated/`(한글 카드), 확인용 미리보기 |
|  |  |  |  |

지우기(7단계)와 한글 넣기(8단계)를 나눈 이유: 번역이 마음에 들지 않을 때 엑셀만 고쳐 다시 가져오면, 오래 걸리고 결과가 매번 조금씩 달라질 수 있는 지우기를 건너뛰고 한글만 다시 넣을 수 있다. 지운 결과(`cleared/`)를 한 번 확인해 두면 번역을 몇 번 바꿔도 배경은 그대로다.

처음 구상한 5단계에서 ‘추출·번역’을 추출 → 용어집 → 번역의 세 단계로 나눴다. **번역은 모든 파일의 추출이 끝난 뒤에만 시작한다.** 전체 카드를 보고 나서야 어떤 단어가 게임 용어인지 알 수 있고, 용어집이 확정되기 전에 번역하면 카드마다 같은 용어가 다르게 번역되기 때문이다. 추출 중 몇 장이 실패하면 그 카드를 다시 추출하거나 제외하는 것을 골라야 다음으로 넘어간다.

### 단계 사이의 안전장치

- **2단계 뒤:** 영역을 다른 카드 여러 장에 겹쳐 보며 글자가 잘리지 않는지 확인한 뒤에야 추출을 시작할 수 있다. 카드가 조금씩 밀려 있어도 자동 정렬(5.8절)로 맞춘 뒤 겹쳐 보여 준다. 카드마다 본문 길이가 다르므로 영역은 가장 긴 카드에 맞춰 넓게 잡는다.
- **2단계 뒤 (글꼴):** 영역마다 한글 글꼴을 묻는다(5.7절 ‘글꼴 묻는 순서’). 원문 모양을 보고 고른 후보 3개를 견본과 함께 보여 주고, 사용자가 고른 글꼴을 영역 설정에 저장한다. 답하지 않으면 1순위 후보를 ‘임시’로 쓰고 8단계 전 확인 목록에 올린다.
- **테스트 실행(언제든):** 페이지를 몇 개 골라(예: `1, 5, 12-14`) 추출→번역→합성을 끝까지 돌려 본다. 결과는 따로 저장되고 본 작업에는 영향을 주지 않는다(5.9절). 전체 300장을 돌리기 전에 영역·서식·아이콘이 제대로 나오는지 여기서 확인한다.
- **3단계 뒤:** 이름이 없는 아이콘이 남아 있으면 다음 단계로 넘어갈 수 없다. 글자를 읽지 못했거나 결과가 불확실한 칸은 나중에 엑셀에서 노란색으로 표시한다.
- **4단계 뒤:** 번역이 비어 있는 용어가 있으면 목록을 보여 주고, 그대로 둘지(모델이 자유롭게 번역) 물는다.
- **7단계 뒤:** 전후 비교를 보고 지우기 결과를 확인한다. 배경이 상한 카드가 있으면 영역을 고쳐 그 카드만 다시 지운다. `cleared/`가 없으면 8단계로 넘어갈 수 없다.
- **8단계 전:** 행이 빠졌거나, 원문이 바뀌었거나, 번역이 비어 있거나, `[[단어]]`나 서식 태그가 빠졌거나, 용어집과 다른 번역이 있으면 합성 전에 목록으로 알려 주고 계속할지 물는다.
- **8단계 뒤:** 번역이 마음에 들지 않으면 엑셀을 고쳐 다시 가져온다. 지우기는 하지 않고 `cleared/`의 카드 위에 한글만 다시 넣어 `translated/`를 갱신한다(P1: 바뀐 행의 카드만). 영역이 바뀌었을 때만 7단계부터 다시 한다. 검수→한글 넣기를 여러 번 반복하는 것이 기본 사용 방식이다.

## 3. 기능 요구사항

1차 입력은 **PDF**다. 캡처 이미지는 같은 흐름으로 처리하되 P1로 둔다. ID는 앞서 쓴 번호를 유지하고 우선순위별로 묶었다.

| ID | 기능 | 우선순위 | 완료 조건 |
| --- | --- | --- | --- |
| F1 | PDF 여러 개 선택 | P0 | PDF 여러 개를 고르면 페이지마다 카드 한 장으로 목록이 나온다. 페이지에 텍스트 레이어가 있는지 자동 판별해 표시한다 |
| F2 | 영역 지정 | P0 | 첫 카드에서 사각형을 그리고 옮기고 크기를 바꾸고 지울 수 있다. 여러 개에 각각 이름을 붙인다 |
| F3 | 영역 미리보기 | P0 | 지정한 영역을 다른 카드 위에 겹쳐 넘겨 보며 확인할 수 있다 |
| F21 | 자동 정렬 | P0 | 카드가 조금씩 밀리거나 크기가 달라도 첫 카드에 맞춰 영역을 옮긴다. 맞추지 못한 카드는 표시하고 손으로 조정할 수 있다(5.8절). **2026-11-12 구현:** 영역 지정 창 ‘자동 정렬’, 파일 폴더 `align.json`, Ctrl+화살표로 그 카드만 미세 조정, 미리보기 ‘정렬 확인 카드만’ |
| F24 | 테스트 실행 | P0 | 고른 페이지만 추출→번역→합성을 끝까지 돌려 전후 비교를 보여 주고, 본 작업 결과에는 영향을 주지 않는다(5.9절) |
| F4 | 텍스트 추출 | P0 | 모든 카드·영역의 글자를 읽고 줄바꿈을 유지한다. PDF는 글자와 함께 글꼴·크기·색·굵기·기울임을 꺼낸다 |
| F26 | 영어·일본어 원문 | P0 | 영어와 일본어를 원문으로 처리한다. 일본어는 띄어쓰기가 없어도 용어 후보·등장 횟수가 제대로 나온다(5.2절) |
| F5 | 아이콘 치환·백업 | P0 | 문장 안의 아이콘을 `[[coin]]`처럼 이중 대괄호로 감싼 단어로 바꾸고, 아이콘 이미지를 배경 없이 잘라 백업한다. 같은 아이콘은 카드가 달라도 같은 단어로 묶는다 |
| F6 | 아이콘 사전 | P0 | 아이콘마다 이름, 원본 이미지, 뜻, 한국어 이름을 저장하고, 추출 뒤 화면에서 이름을 확인·수정할 수 있다 |

## 4. 엑셀 형식

엑셀은 사람과 앱이 주고받는 유일한 문서다. 사람이 보기 편하면서도, 다시 가져올 때 어느 카드의 어느 영역인지 틀림없이 찾을 수 있어야 한다.

### 시트 `번역` (한 행 = 카드 한 장의 영역 하나)

| 열 | 이름 | 누가 채우나 | 설명 |
| --- | --- | --- | --- |
| A | key | 앱 (잠금) | `파일명#영역명`. PDF처럼 한 파일에 카드가 여러 장이면 `파일명#p쪽#영역명`(예: `Dungeon.pdf#p4#본문`). import는 이 값으로 행을 찾는다. 행 순서를 바꿔도 된다 |
| B | 카드 | 앱 | 파일 이름 |
| C | 영역 | 앱 | 영역 이름(제목, 본문 등) |
| D | 미리보기 | 앱 | 그 영역을 잘라낸 작은 이미지. 검수자가 원본을 열지 않고 아이콘 위치까지 확인한다 |
| E | 원문 | 앱 → 사람이 고칠 수 있음 | 추출한 외국어. 아이콘은 `[[coin]]`처럼 이중 대괄호로 감싼 단어로 들어 있다 |
| F | 원문 확인 | 앱 | 원문을 어떻게 얻었는지: `Sonnet 1회`(Sonnet만으로 읽음), `두 번 확인`(Sonnet이 불확실해 Opus로 다시 읽어 같음, 연두), `결론 못 냄`(두 번 읽어도 다르거나 Opus도 불확실, 주황; 원문 칸 메모에 두 결과), `Opus 1회`, `라벨 색`(태그를 색으로 정함), `손 입력`. 확인 필요가 남았으면 뒤에 `(확인 필요)` |
| G | 초벌 번역 | 앱 (잠금) | 기계 번역 그대로. 비교용 |
| H | **번역** | 사람 | 처음에는 G와 같은 값. **한글 넣기(8단계)에는 이 열만 쓴다.** 태그처럼 칸이 여러 개인 영역은 한 줄에 하나씩(셀 안 줄바꿈) 적는다 |
| I | 글자 크기 | 사람 (선택) | 비워 두면 자동. 숫자를 넣으면 그 크기로 고정 |
| J | 상태 | 앱 | 확인 필요(추출 불확실) / 용어 불일치 / 아이콘 불일치 / 서식 불일치 / 글자 축소 / 빈 영역. 여러 개면 모두 적는다 |
| K | 사용한 용어 | 앱 | 이 원문에 들어 있는 용어집 항목(예: `Gold → 금화, Draw → 뽑기`). 검수자가 따로 용어집을 찾지 않아도 된다 |
| L | 메모 | 사람 | 자유 기록. 합성에 영향 없음 |
| M | 그룹 | 앱 | 이 파일이 속한 그룹(예: `BATTLE·DUNGEON`) |
| N | 글꼴 | 앱 | 이 영역에 쓰는 한글 글꼴(예: `Gaegu Bold (Gaegu-Bold.ttf)`). 자세한 설정은 `글꼴` 시트 |

다시 내보내기(`--force`)를 해도 사람이 고친 칸(번역이 초벌 번역과 다르거나, 메모·글자 크기를 적은 행)의 번역·메모·글자 크기는 이전 엑셀에서 옮겨 담는다.

### 작성 규칙

- 줄바꿈은 셀 안 줄바꿈(Alt+Enter)으로 넣는다. 줄바꿈을 넣으면 자동 줄바꿈 대신 그대로 쓴다.
- `[[단어]]`는 번역문에서 아이콘이 들어갈 자리다. 이중 대괄호와 단어를 그대로 쓰고, 한국어 어순에 맞게 위치만 옮긴다. 예: `Pay 2 [[coin]]` → `[[coin]] 2개를 지불한다.`
- 아이콘을 빼거나 더 넣는 것도 허용한다. 다만 import 때 ‘아이콘 불일치’로 표시해 의도한 것인지 한 번 더 확인한다. 아이콘 사전에 없는 `[[단어]]`는 오류다.
- 아이콘을 대괄호 두 겹(`[[ ]]`)으로 감싸는 이유: 카드 문장 자체에 대괄호가 인쇄된 경우가 많다(예: `[4階層]`, `[炎]`, `[人族]`). 한 겹이면 이런 글자와 아이콘 자리를 구분할 수 없다. 카드에 인쇄된 대괄호는 번역문에서도 보통 대괄호 한 겹으로 쓴다(예: `[4층]에 있을 때`). 앱은 `[[…]]`만 아이콘으로 보고, `[…]` 한 겹은 그냥 글자로 그린다.
- 영역을 비우고 싶으면(글자만 지우기) H(번역)에 `-` 하나만 쓴다. 완전히 빈 칸은 ‘아직 번역 안 함’으로 본다.
- 같은 원문이 여러 카드에 나오면 초벌 번역은 같게 넣는다. 검수자가 한 곳만 고치면 나머지는 그대로다(자동 전파는 하지 않고, import 때 ‘같은 원문인데 번역이 다른 행’을 알려 준다).
- 한 문장 안에서 서식이 바뀌는 부분은 원문에 `<b>…</b>`(굵게), `<i>…</i>`(기울임) 태그로 표시된다. 번역문에서는 대응하는 한국어 단어를 같은 태그로 감싼다. 예: `Gain <b>2 Gold</b>.` → `<b>금화 2개</b>를 얻는다.` 문장 전체가 같은 서식이면 태그를 쓰지 않고 영역의 기본 서식을 따른다.

### 보조 시트

- `아이콘`: 원문에 든 아이콘의 위치 목록. 한 줄 = 아이콘 하나: key, 카드(쪽), 영역, 줄, 줄에서 순서, `[[단어]]`, 사전 그림, 상태, 번역에 있음. 상태가 `이름 없음`(아이콘 검증 필요)·`사전에 없음`(합성 안 됨)·`자동으로 맞춤`(다른 프로젝트 사전과 모양이 같아 바꿈, 확인 권장)이면 주황으로 칠해 검증할 곳을 바로 찾게 한다. `정보` 시트에 확인할 아이콘 수를 적는다(읽기 전용).
- `글꼴`: 영역마다 그룹, 종류, 글꼴 이름, 글꼴 파일, 대체 글꼴(글꼴에 없는 글자), 굵은 글꼴, 색, 정렬, 회전, 고른 이유(읽기 전용).
- `용어집`: 4단계에서 확정한 용어집 전체(읽기 전용). 용어를 바꾸려면 이 시트가 아니라 `용어집.xlsx`를 고쳐 다시 가져온다(F20).
- `정보`: 프로젝트 이름, 내보낸 시각, 앱 버전, 원문 언어, 용어집 버전. import 때 다른 프로젝트의 엑셀을 잘못 고른 것을 걸러낸다.

### `용어집.xlsx` (4단계에서 주고받는 파일)

| 열 | 이름 | 누가 채우나 | 설명 |
| --- | --- | --- | --- |
| A | 원문 용어 | 앱 → 사람이 추가 가능 | 단어 또는 구(예: `Gold`, `Draw a card`). 아래에 행을 더해 용어를 직접 추가할 수 있다 |
| B | **번역** | 사람 | 항상 쓸 한국어. 비워 두면 용어로 쓰지 않는다. 동사·동작어는 문장에 맞게 활용해 쓴다(예: `버리다` → 버린다·버려진다). 뜻과 어감은 바꾸지 않는다 |
| C | 추천 번역 | 앱 | 모델이 예문을 보고 제안한 번역. 기존 용어집에 있던 용어는 그 번역이 B에 미리 들어 있다. 확인할 정보(D~F)는 번역 바로 옆에 둔다 |
| D | 원문 상태 | 앱 | 이 용어가 나온 원문 칸이 모두 추출이 불확실한 칸이면 그 상태(`결론 못 냄` 주황 / `확인 필요` 노랑)와 칸 위치(셀 메모). 원문 글자 자체가 틀렸을 수 있으니 확인한다. 확실하게 읽은 칸에도 나오면 비운다 |
| E | 번역 확인 | 앱 | 모델이 번역이 갈릴 수 있다고 본 용어(예: 炎 화염/불꽃, 人族 인간족/인간, 음역·번역 선택, 문장 속에서 어색한 명사형 동작어)는 `확인 필요`, 번역 칸과 함께 보라색. 이미 확정된 용어도 매번 다시 본다 |
| F | 다른 후보 | 앱 | 대안 번역 1~3개와 이유 |
| G | 분류 | 앱 → 사람 | 카드 이름 / 키워드·능력 / 자원·토큰 / 행동 / 기타 |
| H | 등장 횟수 | 앱 | 전체 카드에서 나온 횟수. 많이 나오는 용어부터 정렬 |
| I | 예문 | 앱 | 이 용어가 들어간 원문 1\~2개와 카드 이름 |
| J | 변형 | 사람 (선택) | 복수형·활용형 등 같은 용어로 볼 형태(예: `Golds, gold`). 앱이 기본적인 변형은 채워 둔다 |
| K | 메모 | 사람 | 번역 이유, 판별 차이 등 |

- 같은 게임의 용어집은 프로젝트가 아니라 게임 단위로 저장된다. 다음 카드 타입을 작업할 때는 새 용어만 후보로 나오고 기존 용어는 확정된 채로 나온다.
- 한 원문 용어에 번역은 하나만 둔다. 같은 원문을 두 번 적거나 번역이 두 개면 가져올 때 멈추고 알린다.
- 한 번역을 여러 원문이 공유하는 것은 경고만 한다(예: `Gold`와 `Coin`이 모두 ‘금화’).
- ‘번역 확인’ 용어를 추천 번역(또는 이미 확정된 번역) 그대로 가져오면 목록을 보여 주고 확인을 받는다(다른 후보를 봤는지).

### import 규칙

1. `정보` 시트의 프로젝트가 다르면 멈추고 알린다.
2. key로 행을 찾는다. 프로젝트에는 있는데 엑셀에 없는 행, 엑셀에만 있는 행을 모두 목록으로 보여 준다.
3. H(번역)가 빈 행은 한글을 넣지 않는다. 글자는 7단계에서 이미 지웠으므로 그 영역은 빈 채로 남는다. 그래서 빈 행은 ‘확인’ 목록에 올려 계속할지 묻는다.
4. E(원문)를 고친 행은 표시만 하고 합성에는 영향을 주지 않는다(사람이 원문 오류를 알았다는 기록).
5. 문제가 없거나 사용자가 ‘계속’을 고르면 `cleared/`의 지운 카드 위에 한글을 넣는다(지우기는 다시 하지 않음). 엑셀만 고쳐 이 과정을 몇 번이고 반복할 수 있다.

## 5. 핵심 처리

### 5.1 영역 템플릿

영역마다 아래 설정을 저장한다. 좌표는 픽셀이 아니라 카드 너비·높이 대비 비율(0\~1)로 저장해, 해상도가 조금 다른 파일에도 같은 영역을 쓸 수 있게 한다.

| 설정 | 기본값 | 설명 |
| --- | --- | --- |
| 이름 | 영역1 | 엑셀의 ‘영역’ 열에 나오는 이름 |
| 좌표 | — | x, y, 너비, 높이 (비율). 카드별로는 자동 정렬 결과만큼 옮겨 적용한다 |
| 지우는 방식 | 자동 | PDF 텍스트 지우기 / 단색 채우기 / 배경 복원. 자동은 텍스트 레이어가 있으면 PDF 텍스트 지우기, 없으면 배경에 따라 단색 또는 복원 |
| 글꼴 | 원문 따름 | 원문 글꼴 계열(고딕/명조/장식)에 맞는 한글 글꼴을 고른다(5.7절). 직접 지정하면 그 글꼴 |
| 글자색·크기·굵기·기울임 | 원문 따름 | PDF는 글자에 든 값을 그대로, 이미지는 픽셀에서 추정한 값을 쓴다. 영역별로 덮어쓸 수 있다 |
| 최소 글자 크기 | 원문 글자 높이의 80% | 넘칠 때 여기까지만 줄이고, 그래도 넘치면 ‘넘침’으로 표시한다. 기준은 pt가 아니라 실제 글자 높이(잉크 높이)다: 한글 글자 높이가 원문 글자 높이의 80% 아래로 내려가지 않는다. 원문 글자 높이를 잴 수 없을 때만 pt 기준(원문의 80%, 6pt 아래로는 내리지 않음, 원문이 6pt 미만이면 원문 크기)을 쓴다 (2026-11-04 결정) |
| 정렬 | 원문 따름 | 원문 줄들의 위치로 왼·가운데·오른쪽을 추정한다. 직접 지정 가능 |
| 줄 간격·여백 | 원문 따름 | 원문 줄 사이 간격을 재서 쓴다. 한 줄짜리는 1.2배 |
| 번역 안 함 | 꺼짐 | 켜면 추출만 하고 번역은 비워 둔다(숫자·고유명사 영역용) |

### 5.2 텍스트 추출

입력에 따라 두 길로 나뉜다.

- **PDF에 텍스트 레이어가 있는 경우 (기본 경로):** 글자를 인식할 필요 없이 영역 안 텍스트를 그대로 꺼낸다. 한 글자 덩어리(span)마다 글꼴 이름, 크기, 색, 굵기·기울임 여부를 함께 저장해 서식 유지(5.7절)에 쓴다. 아이콘은 텍스트 사이의 그림 객체나 아이콘 전용 글꼴 문자로 찾는다.
- **텍스트 레이어가 없는 PDF 페이지·캡처 이미지 (P1):** 페이지를 300dpi로 이미지화하고 영역을 잘라 Claude 비전으로 읽는다. 장식 글꼴·배경 그림이 섞여 있어 일반 OCR이 자주 틀리기 때문이다. 로컬 OCR(PaddleOCR)은 비용 없는 대안으로 둔다.
- **글자가 이상하게 나오는 PDF:** 폰트에 문자 대응표가 없어 깨진 글자(□, 엉뚱한 기호)가 일정 비율 이상이면, 그 페이지는 글자 내용만 비전으로 읽고 서식·위치는 텍스트 레이어 값을 그대로 쓴다.
- **일본어:** 띄어쓰기가 없으므로 용어 후보·등장 횟수는 형태소 분석기(SudachiPy)로 단어를 나눌 세다. PDF에서 줄이 끊긴 곳은 일본어는 공백 없이 잇고, 영어는 하이픈을 처리해 잇는다. 요미가나(루비)는 원문에서 빼고 따로 기록한다.
- **아이콘:** 추출 전에 아이콘 위치를 먼저 찾고, 문장 안 제자리에 `[[coin]]`을 넣는다(5.6절).
- 읽기 어려운 부분은 ‘확인 필요’로 표시한다. 추출은 모든 카드를 끝까지 돌리고, 번역은 이 단계에서 하지 않는다.
- **ClearScan PDF (실제 1차 입력, 2026-11-04 확인):** 스캔본을 Acrobat ‘ClearScan’으로 저장한 PDF는 원래 글자를 배경 이미지에서 지우고, 그 위에 합성 글꼴(`Fd1058` 등)로 다시 그린 벡터 글자를 얹는다. 이 경우 아래처럼 섞어서 쓴다.
  - **위치·크기·색:** 텍스트 레이어 값을 쓴다.
  - **글자 내용:** 텍스트 레이어를 믿지 않고 비전으로 읽는다. 1단계에서는 손으로 입력한다. 실제 샘플에서는 카타카나 제목이 깨지고 본문에도 오인식(の→申 등)이 많았다.
  - **굵기·기울임:** 글꼴 이름으로 알 수 없으므로 영역 설정으로 정한다.
  - **누락된 글자:** 일부 카드는 제목·태그가 텍스트 레이어에 잡히지 않고 이미지에 그대로 남아 있다. 그래서 텍스트 레이어에 의존하지 않고 영역 단위로 처리한다.

**비전 추출 방식 (2026-11-04 결정)**

- **읽는 방법(엔진) 선택:** 기본은 `claude-code`다. 로그인된 Claude Code를 헤드리스 모드(`claude -p`)로 불러, 카드마다 영역 이미지를 파일로 만들어 읽게 한다. API 키와 별도 결제가 필요 없고 Claude Code 요금제 사용량을 쓴다. 사용 한도에 걸리면 일시 정지했다가, 한도가 풀린 뒤 다시 실행하면 이어 간다. 카드 한 장 ≈ 10초(실측). Claude Code 기본 지시문 때문에 API 정가로 환산하면 장당 약 $0.08이지만, 따로 청구되지는 않는다. 옵션 `api`는 Anthropic API를 쓴다(`.env`의 키 또는 `ant auth login`, 사용료 별도). 일괄 처리(`--batch`)와 예산(`--budget`)은 `api`에서만 쓴다.
- **읽기 모드(2026-11-04 결정):** 잘못 읽은 글자가 뒤 단계로 넘어가 꼬이는 것을 가장 크게 보고 두 가지만 둔다.
  - `double-check`(기본): Sonnet 5.5로 전부 읽고, ‘확인 필요’로 표시된 칸만 Opus 5.5로 다시 읽는다. 두 모델이 같게 읽고 Opus도 확실하면 ‘확인 필요’를 지운다. 다르게 읽거나 Opus도 확실하지 않으면 Opus 쪽을 원문으로 쓰고, 두 결과를 메모에 남기고, ‘확인 필요’를 유지한다. 다시 읽은 칸은 기록해 두 번 하지 않으며, 중간에 멈춰도 이어 간다.
  - `opus`: Opus 5.5만으로 전부 읽는다. 가장 정확하지만 요금제 한도를 빨리 써서 중간에 자주 멈춘다.
- **요청 방식:** 카드 한 장에 요청 한 번으로, 영역마다 원본을 잘라(400dpi, 180도 영역은 바로 세워) 영역 이름과 함께 보낸다. 응답은 구조화 출력(JSON 스키마)으로 받는다. 영역별 `원문`, `불확실 여부`, `메모`가 들어 있고, 불확실한 칸은 엑셀에서 노란색 ‘확인 필요’로 표시한다. 거절되면 서버 쪽 대체 모델(`fallbacks: "default"`, Opus·Sonnet만)로 다시 읽는다.
- **비용(추정):** 카드 한 장 ≈ 입력 2,000 토큰 + 출력 600 토큰 ≈ $0.02. 일괄 처리를 쓰면 절반이다. 카드마다 실제 사용량과 비용을 결과 파일에 적는다.
- **이어 하기:** 결과는 카드마다 `extract/pages/page-NNN.json`에 바로 쓴다. 다시 실행하면 이미 읽은 카드는 건너뛴다. 아래 경우에는 그 자리에서 멈추고 `extract/state.json`에 ‘일시 정지’, 이유, 다시 해도 되는 시각을 적는다. 같은 명령을 다시 실행하면 남은 카드부터 이어 간다.
  - API 속도 제한(429), 서버 과부하·오류, 네트워크 오류
  - 크레딧·사용 한도 부족
  - 사용자가 정한 예산(`--budget`) 도달
  - 사용자 취소
- **카드 한 장만의 문제:** 이미지가 너무 큰 경우처럼 그 카드의 요청만 잘못됐거나, 응답이 거절·잘림이면 그 카드만 ‘실패’로 표시하고 나머지를 계속한다. 실패한 카드는 `--retry-failed`로 다시 읽는다.
- **일괄 처리 옵션(`--batch`):** Message Batches API로 보낸다. 50% 할인 대신 결과가 늦게 온다(보통 1시간 안, 최대 24시간). 보낸 작업 ID를 `state.json`에 저장하므로 앱을 껐다 켜도 그 결과를 받아 온다. 서버 오류·만료된 카드만 새 작업으로 다시 보낸다. 일괄 처리에는 대체 모델 기능이 없어, 거절된 카드는 ‘실패’로 남긴다.
- **태그(색 라벨):** 라벨 안 작은 흰 글자는 스캔·ClearScan 과정에서 뭉개져 비전으로도 읽을 수 없다(900dpi로도 덩어리). 같은 게임에서 라벨 색과 글자는 1:1이므로, 글자를 아는 카드에서 ‘라벨 색 → 글자’ 사전을 배워(`learn-tag-colors`) 영역 설정 `extract.tag_colors`에 저장하고, 추출 때 라벨 색으로 글자를 정한다. 비용이 들지 않는다. 사전에 없는 색이 섞인 카드만 비전으로 읽고, 알려진 단어 목록을 힌트로 준다.
- **실측(2026-11-04, Dungeon 1~5쪽 + Items 2~6쪽, 45칸):**
  - Opus: 이름·본문·효과 40칸 중 39칸 정확
  - Sonnet: 45칸 중 40칸 정확. 태그 5칸은 색 사전으로 모두 정확. 틀린 5칸 중 3칸은 ‘확인 필요’로 표시됨. 표시되지 않은 2칸은 대시 모양(—— / ーー)과, 원본이 뭉개져 정답도 불확실한 한자 1칸이다.
  - 두 번 확인(Sonnet + 불확실한 5칸만 Opus): 45칸 중 42칸 정확. 남은 틀린 3칸 중 실제로 잘못 읽은 1칸(盗掘→盗賊, 두 모델 모두 같게 틀림)은 ‘확인 필요’로 남음. 표시 안 된 2칸은 대시 모양과 정답이 불확실한 한자.
- **정확도 확인:** 손으로 옮긴 원문(`samples.json`)이 있으면 `extract-eval`로 칸별 일치율을 잰다. 공백과 전각·반각 차이는 무시한다. 틀린 칸 중 몇 개가 ‘확인 필요’로 표시됐는지도 함께 본다(완료 기준: 정확도 95% 이상, 틀린 칸 대부분이 ‘확인 필요’).
- **API 키(`api` 엔진):** 찾는 순서는 환경 변수 `ANTHROPIC_API_KEY` → 화면에서 저장한 키 → 데이터 폴더(또는 개발 중 저장소)의 `.env` → `ant auth login` 프로필이다. 화면에서 넣은 키는 토큰을 쓰지 않는 요청(모델 목록)으로 확인한 뒤, Windows DPAPI로 이 컴퓨터의 이 사용자만 풀 수 있게 암호화해 `%APPDATA%\CardTranslater\api_key.bin`에 저장한다. 키 값은 소스 코드·프로젝트 폴더·로그·화면에 남기지 않는다(화면에는 `sk-ant-…abcd`처럼 일부만). 키가 없으면 오류로 멈추지 않고 ‘사용할 수 없음’ 상태와 안내를 돌려준다.

### 5.3 번역

번역은 두 번에 나눠 한다. 먼저 용어집을 확정하고, 그다음 문장을 번역한다. 보드게임은 같은 용어가 카드마다 다르게 번역되면 규칙을 잘못 읽게 되므로, 용어 통일이 번역 품질보다 우선이다.

**가. 용어집 만들기 (사용자가 ‘추출 완료’를 보낸 뒤)**

0. ‘추출 완료’를 받으면 먼저 프로젝트의 모든 그룹·파일의 추출 상태를 보여 준다. 아직 읽지 않은 카드, 실패한 카드, ‘결론 못 냄’ 칸이 있으면 목록을 보여 주고 계속할지 묻는다(읽지 않은 카드가 있으면 기본은 멈춤).
1. 전체 원문을 한꺼번에 모델에 보내 용어 후보를 뽑는다. 카드 이름, 대문자로 시작하는 키워드, 자원·토큰 이름, 반복되는 행동 문구(예: `Draw a card`), 아이콘의 뜻이 대상이다.
1-1. **문구:** 조사·어미가 붙은 긴 구절(예: `すべての判定にボーナスがもらえる`, `ダイスを振り`)은 용어가 아니라 ‘문구’로 분류한다. 번역 때 권장 표현으로만 주고 용어 불일치 검사는 하지 않는다. 글자가 조금만 달라도 불일치가 나서 오히려 검수를 방해하기 때문이다. 기준: 카드 이름·태그가 아니고, 11자 이상이거나 조사(を・に・が・は・で・へ・と・も)나 문장 부호가 들어 있으면 문구.
2. 코드로 등장 횟수를 세고 예문을 붙인다. 2회 이상 나오는 명사구는 모델이 놓쳤어도 후보에 더한다. 카드에 대괄호로 인쇄된 분류어(예: `[炎]`, `[人族]`)와 태그 라벨 글자는 코드로 모두 후보에 넣는다.
3. 게임 용어집에 이미 있는 용어는 그 번역을 채우고, 새 용어에만 추천 번역을 붙여 `용어집.xlsx`로 내보낸다.
4. 사용자가 검증해 가져오면 용어집이 확정된다. 확정 전에는 번역을 시작할 수 없다.
5. **용어집 검증(가져올 때 코드로):** 같은 원문 용어가 두 번 있으면 멈춘다. 번역이 빈 용어는 ‘용어로 쓰지 않음’ 목록으로 보여 주고 계속할지 묻는다. 한 번역을 여러 원문이 함께 쓰면 경고한다. 다른 게임의 용어집 파일이면 멈춘다.
6. 확정 뒤에 파일을 더 추가해 다시 ‘추출 완료’를 보내면, 이미 확정된 용어는 그대로 두고 새 후보만 검증한다. 확정 용어를 바꾸면 번역을 다시 해야 하는 행을 알려 준다(F20).
7. 용어 후보 뽑기에도 추출과 같은 엔진(기본: Claude Code 요금제)과 이어 하기 규칙을 쓴다.

**나. 문장 번역**

- 한 문장을 보낼 때, 그 문장에 들어 있는 용어와 확정 번역을 함께 보내 ‘이 번역을 반드시 쓸 것’을 지시한다. 전체 용어집은 프롬프트 앞부분에 두고 캐시한다.
- `[[단어]]`는 그대로 두되, 한국어 어순에 맞게 위치를 옮기도록 한다. 각 아이콘의 뜻·한국어 이름·쓰임을 함께 주어 조사를 맞게 붙이게 한다(5.6절).
- 같은 원문은 한 번만 번역하고 결과를 저장해 두어 다시 돌려도 비용이 들지 않게 한다.
- 여러 문장을 묶어 한 번에 보내 카드 간 말투가 맞게 한다. 게임 이름과 장르, 영역 이름(제목은 짧게, 본문은 규칙 문체), 영역 크기에 맞는 대략적인 글자 수도 함께 준다.
- 결과는 JSON으로 받아 행이 밀리지 않게 한다.

**구현 (2026-11-04)**

- 모델: 기본 Sonnet 5.5(옵션 Opus 5.5). 엔진은 추출과 같다(기본 Claude Code 요금제).
- 서로 다른 원문만 번역하고 프로젝트 번역 캐시(`translate/cache.json`)에 저장한다. 같은 원문은 모든 카드에서 같은 번역을 쓴다.
- 칸 전체가 확정 용어와 같으면(카드 이름, 태그 라벨) 모델을 부르지 않고 용어집 번역을 그대로 쓴다.
- 30칸씩 묶어 보내고, 그 묶음에 나오는 용어와 확정 번역을 함께 준다. 줄 수는 원문과 같게 하고, 「」는 “ ”로, 카드 대괄호 `[炎]`는 `[불꽃]`처럼 대괄호를 남긴다.
- 한 글자 용어(예: 魔)는 다른 단어(悪魔) 안에서는 용어로 보지 않는다. 칸 전체가 그 글자이거나 `[魔]`처럼 대괄호 안에 있을 때만 용어로 센다(용어집 등장 횟수에도 같은 규칙).
- 용어집이 바뀌면 번역이 바뀐 용어가 든 칸만 다시 번역한다.
- 묶음마다 저장하므로 한도에 걸려 멈춰도 다시 실행하면 남은 칸부터 이어 간다.
- 번역 검수 엑셀의 ‘초벌 번역’·‘번역’ 열에 초벌 번역을 넣고, ‘상태’에 용어·아이콘 불일치를, ‘사용한 용어’에 그 칸의 용어(`炎 → 불꽃`)를 적는다.

**다. 번역 뒤 검사 (코드로)**

- 원문에 용어(변형 포함)가 있는데 번역문에 확정 번역이 없으면 ‘용어 불일치’. 한 번 더 모델에 고쳐 달라고 요청하고, 그래도 안 되면 엑셀에 표시만 한다.
- 원문과 번역문의 `[[단어]]` 종류·개수가 다르면 ‘아이콘 불일치’.
- 같은 검사를 검수한 엑셀을 가져올 때 다시 한다. 사람이 고친 번역도 용어집을 지켰는지 확인하기 위해서다.

### 5.4 글자 지우기

1. **PDF 텍스트 레이어가 있을 때 (기본):** 영역 안의 텍스트 객체와 아이콘 객체만 지운다(레드랙션). 채우기 색을 쓰지 않고 그림·도형은 지우지 않도록 설정해, 배경색·그라데이션·무늬가 그대로 남는다. 배경 복원이 필요 없다.
2. **글자가 그림에 박혀 있을 때 (P1):** 영역 가장자리 픽셀로 배경색을 추정하고, 배경과 다른 픽셀을 글자로 본다(글자 마스크). 마스크를 2\~3픽셀 넓혀 테두리·그림자까지 덮고, 배경이 고르면 추정한 색으로, 질감이 있으면 배경 복원(인페인팅)으로 채운다.
3. **ClearScan PDF (실제 1차 입력, P0):** 1번과 2번을 함께 쓴다.
   - 영역 안의 텍스트 객체를 레드랙션으로 지운다.
   - 그 아래 배경 이미지에 남은 흔적을 2번 방식(마스크 → 채우기·인페인팅)으로 정리한다. 남는 흔적은 Acrobat이 지운 자리의 얼룩·블록 자국과, 텍스트 레이어에 잡히지 않아 이미지에 남은 글자다.
   - 색 라벨(태그) 안의 글자는 라벨 모양째 글자로 잡혀 있어서, 지우면 라벨까지 사라진다. 그래서 라벨을 원래 색·모양(둥근 사각형)으로 다시 그린 뒤 한글을 올린다.
   - 배경 이미지가 조금(1~2도) 돌아가 있으면(Acrobat이 기울어진 스캔을 바로 세운 경우) 이미지 격자대로 정리하고, 패치도 같은 각도로 덮어 원본 이미지 스트림은 그대로 둔다.
   - 텍스트 레이어가 없는 스캔 PDF(예: ScanSnap 원본)도 2번 방식으로 지운다. 글자 위치는 이미지에서 찾고(종이보다 뚜렷이 어두운 잉크), 작업 범위를 실제 글자 + 약간의 여유로 줄인다. 영역 안에 걸친 큰 잉크 덩어리(그림, `+2` 같은 큰 숫자)는 영역마다 정한 높이(`erase.keep_ink_taller_than_pt`)보다 크면 글자가 아니라고 보고 남긴다. 작업 범위 밖의 그림·색 번짐은 배경 추정에 쓰지 않는다(얼룩 방지). 글자 줄에 바짝 붙은 작은 그림(예: 이름 위 왕관 아이콘)은 `erase.keep_ink_above_text`로 표시한 영역에서 글자 줄보다 완전히 위에 있으면 남긴다(180도 돌린 영역은 방향을 뒤집어 판단).
4. **확인:** 지운 직후 영역의 원본·결과를 나란히 저장해, 테스트 실행에서 배경이 손상됐는지 볼 수 있게 한다. 배경에 변화가 크면(글자가 아닌 픽셀이 많이 바뀜) 표시한다.

### 5.5 한글 배치

- 글자 크기는 원문 크기에서 시작한다. 넘치면 ① 어절 단위로 줄을 다시 나누고 ② 자간을 조금(최대 −5%) 좁히고 ③ 그래도 넘치면 최소 크기(원문 글자 높이의 80%)까지 줄인다. 글꼴마다 기본 자간을 영역 설정으로 줄 수 있고(예: 개구 Bold −8%), ②는 그 값에서 더 좁힌다. 줄인 칸은 ‘글자 축소’, 그래도 안 들어간 칸은 ‘넘침’으로 표시한다.
- 줄바꿈은 어절(띄어쓰기) 단위. 한 어절이 한 줄보다 길 때만 글자 단위로 끊는다. 문장 부호(마침표, 쉼표, 닫는 괄호)로 줄을 시작하지 않는다.
- `[[단어]]`는 백업한 아이콘 이미지로 바꿔 그린다. 아이콘과 바로 붙은 조사는 한 덩어리로 보아 줄이 갈리지 않게 한다(예: `[[coin]]을`). 크기·위치 규칙은 5.6절.
- 글자색·굵기·기울임은 5.7절 규칙을 따른다.
- 거꾸로 인쇄된 영역(예: 카드 위아래 반쪽에 아이템이 하나씩 있고 위쪽이 180도 돌아간 카드)은 영역 설정 `rotate: 180`으로 표시한다. 원문 측정과 배치는 돌린 틀(바로 선 상태)에서 하고, 그릴 때만 영역 중심 둘레로 180도 돌린다. 지금은 180도만 지원한다(90도 세로 영역은 열린 질문).
- PDF에는 한글을 벡터 텍스트로 넣고 쓴 글자만 글꼴을 내장한다(서브셋). 인쇄해도 글자가 깨끗하고 파일이 커지지 않는다.
- 같은 영역은 글자 크기가 들쭉날쭉하지 않도록 ‘크기 통일’ 옵션을 둔다(가장 많이 줄어든 카드에 맞춰 모두 통일).

### 5.6 아이콘 처리

카드 문장에는 아이콘이 끼어 있을 수 있다. 아이콘은 번역하지 않고 원본 그림을 그대로 다시 쓴다. 텍스트에서는 이중 대괄호로 감싼 단어(예: `[[coin]]`)가 아이콘을 대신한다.

**두 가지 쓰임**

| 쓰임 | 원문 예 | 추출 결과 | 번역 예 |
| --- | --- | --- | --- |
| 보조형 — 앞 단어와 같은 뜻으로 덧붙임 | Gain 2 Gold 🪙 | `Gain 2 Gold [[coin]]` | `금화[[coin]] 2개를 얻는다.` |
| 대체형 — 단어 대신 아이콘만 씀 | Pay 2 🪙 | `Pay 2 [[coin]]` | `[[coin]] 2개를 지불한다.` |

쓰임은 아이콘마다가 아니라 등장할 때마다 정한다. 아이콘 바로 앞 단어가 그 아이콘의 뜻(또는 용어집 변형)과 같으면 보조형, 아니면 대체형으로 자동 판단한다. 번역 지침은 이렇다.

- **보조형:** 단어는 용어집대로 번역하고, 아이콘은 그 한국어 단어 바로 뒤에 붙여 둔다.
- **대체형:** 아이콘을 명사처럼 다룬다. 뒤에 붙는 조사는 아이콘의 한국어 이름 받침을 기준으로 고른다(예: 이름이 ‘금화’면 `[[coin]]를`, ‘체력’이면 `[heart]을`). 그래서 아이콘 사전에는 한국어 이름도 저장한다.

**추출 때: 찾기 → 치환 → 백업**

1. **샘플 등록:** 2단계(영역 지정)에서 카드에 보이는 아이콘을 사각형으로 짚고 이름을 붙일 수 있다. 미리 등록할수록 정확하다.
2. **위치 찾기:** 등록된 아이콘은 모든 카드의 영역에서 모양 비교(템플릿 매칭, 크기 여러 단계)로 찾는다. 줄은 글자 덩어리를 세로로 묶어 센다. 영역 위·아래 가장자리에 닿은 조각(카드 테두리·그림), 얇고 긴 가로 구분선과 그 높이의 장식(◆)은 줄로 세지 않는다. 원문 줄 수와 이미지 줄 수가 다르면(추출이 줄을 빠뜨림 등) 줄 길이가 가장 잘 맞는 짝을 고른다. 줄 안에서는 덩어리를 글자 칸으로 묶어(가로로 겹치면 하나, 틈이 좁아도 합친 폭이 글자 하나 이하일 때만 하나, 줄 위·아래 가장자리의 가는 조각과 작은 문장부호는 제외) 원문의 글자 순서와 짝짓는다. 칸 수가 다르면 예상 위치 근처에서 크고 가까운 칸을 고른다. 같은 아이콘인지는 아이콘 안의 진한 선(테두리·무늬)을 비교한다(바깥을 투명하게 한 실루엣만 보면 동전·카드·왕관이 비슷해진다). 잘라 낸 아이콘은 모양 바깥만 투명하게 하고 안쪽(동전의 흰 부분 등)은 살린다. 등록되지 않은 아이콘은 글자가 아닌 색이 있는 덩어리를 후보로 뽑고, 비슷한 모양끼리 묶는다.
3. **치환:** 글자를 읽는 모델은 문장 속 그림을 제자리에 `[[?]]`로 적는다. `find-icons`(또는 ‘추출 완료’)가 그 줄의 잉크에서 원문 글자 순서로 아이콘 덩어리를 찾아(줄 수가 다르거나 아이콘 크기 덩어리가 없으면 ‘위치 못 찾음’) 배경을 투명하게 잘라 낸다. 게임 아이콘 사전과 모양·색이 같으면(모양 상관 0.8 이상, 색 차이 작음) 바로 `[[단어]]`로 바꾸고, 나머지는 같은 모양끼리 묶는다.
4. **백업:** 아이콘마다 대표 이미지 하나를 배경을 투명하게 해 `icons/<단어>.png`로 저장한다. 가장 선명하고 큰 것을 대표로 고르고, 카드별 원본 조각도 함께 보관한다.
5. **이름 확인:** 추출이 끝나면 새로 발견한 아이콘을 모아 `아이콘_검증.xlsx`(묶음, 그림, 제안 이름, 이름, 뜻(원문), 한국어 이름, 처리, 표시 크기, 등장 횟수, 예문)로 보여 주고(`위치` 시트에 모든 등장 위치: 묶음, 카드(쪽), 영역, 줄, 줄에서 순서, 잘라 낸 그림, 위치 찾기 결과), 모델이 제안한 이름(예: `coin`)과 뜻을 사용자가 확정한다. 아이콘이 아닌 것을 잘못 잡았으면 ‘아이콘 아님’으로 빼고, 두 묶음이 같은 아이콘이면 합친다(확정 창의 ‘같은 아이콘’ 칸에서 다른 줄 번호나 사전 아이콘을 고른다. 합치면 대표 그림은 가장 많이 나온 묶음의 그림). ‘카드 보기’로 그 아이콘이 나온 카드 자리와 잘라 낸 그림을 확인한다. 이름이 바뀌면 원문 안의 `[[단어]]`도 함께 바뀐다. 같은 이름을 쓴 묶음은 하나로 합치고, 사전에 있는 이름을 쓰면 사전 그림을 쓴다. `import-icons`로 가져오면 원문의 `[[?]]`가 바뀐다. 이름 없는 아이콘이 남아 있으면 ‘추출 완료’가 용어집 단계로 넘어가지 않는다.

**아이콘 사전 (게임 단위로 저장)**

| 항목 | 예 | 설명 |
| --- | --- | --- |
| 단어 | `coin` | 대괄호 안에 들어갈 이름. 영문 소문자·숫자·`_`만 |
| 이미지 | `icons/coin.png` | 배경을 투명하게 한 대표 이미지 |
| 뜻(원문) | Gold | 보조형 판단과 번역 지침에 쓴다 |
| 한국어 이름 | 금화 | 용어집에서 가져온다. 대체형의 조사 선택에 쓴다 |
| 표시 크기 | 글자 높이의 1.1배 | 합성 때 글자 대비 크기. 아이콘마다 조정 가능 |
| 세로 위치 | 글자 가운데 맞춤 | 글자 기준선에 맞출지, 가운데에 맞출지 (지금은 가운데만) |

**합성 때**

- 글자 지우기는 영역 안의 아이콘까지 같이 지운다. 아이콘은 한글 문장 안 새 위치에 다시 그린다. 한국어 어순이 달라 아이콘 위치가 원본과 달라지기 때문이다.
- 아이콘 너비는 글자 크기에 따라 바뀌므로, 글자 크기 맞추기와 줄바꿈을 계산할 때 아이콘 폭도 함께 계산한다.
- 엑셀의 번역에 아이콘 사전에 없는 `[[단어]]`가 있으면 그 카드는 합성하지 않고 오류 목록에 넣는다.
- 문장 밖에 따로 있는 아이콘(예: 카드 구석의 비용 표시)은 영역에 넣지 않으면 손대지 않는다.

### 5.7 서식 유지

글자를 바꿔도 카드의 인상이 그대로여야 한다. 배경색은 지우기 방식(5.4절)으로 지키고, 글자 서식은 아래처럼 원문에서 가져온다.

| 속성 | PDF에서 가져오는 법 | 한글에 적용하는 법 |
| --- | --- | --- |
| 글자색 | 글자 덩어리의 색 값 | 같은 색 그대로 |
| 크기 | 글자 덩어리의 크기(pt) | 같은 크기에서 시작, 넘치면 최소 80%까지 |
| 굵기 | 글꼴 이름(`Bold`, `Black`, `W6` 등)과 굵기 표시 | 한글 글꼴의 같은 굵기(보통/굵게/아주 굵게) |
| 기울임 | 글꼴 이름(`Italic`, `Oblique`)과 기울임 표시 | 한글 글꼴에는 기울임꼴이 거의 없으므로 글자를 약 12° 기울여 그린다 |
| 글꼴 계열 | 글꼴 이름 | 고딕·산세리프 → 본고딕, 명조·세리프 → 본명조, 장식 글꼴 → 프로젝트에서 지정한 제목용 글꼴. 대응표는 프로젝트 설정에서 바꿀 수 있다 |
| 테두리·그림자 | 글자 외곽선 두께·색(있을 때) | 같은 두께·색으로. 그림자는 영역 설정에서 켜고 끈다 |

- **문장 안에서 서식이 섞인 경우:** 추출 때 영역에서 가장 많이 쓴 서식을 ‘기본 서식’으로 정하고, 이와 다른 부분만 `<b>` `<i>` 태그로 감싼다. 색이 다른 부분은 `<c1>`, `<c2>`처럼 번호를 붙인 색 태그로 표시하고 실제 색은 프로젝트에 저장한다. 번역은 태그를 대응하는 한국어 부분으로 옮기고, 합성은 태그별로 서식을 바꿔 그린다.
- **태그 검사:** 원문과 번역문의 태그 종류·개수가 다르거나 열고 닫는 짝이 맞지 않으면 ‘서식 불일치’로 표시한다. 짝이 깨진 칸은 태그를 무시하고 기본 서식으로 합성한다.
- **이미지 경로(P1):** 글자색은 글자 마스크 픽셀의 대표색, 크기는 줄 높이로 추정한다. 굵기·기울임은 추정이 부정확하므로 영역 설정에서 지정한다.

**어울리는 한글 글꼴 찾기 (F28)**

원문 글꼴 이름만으로는 한글 글꼴을 고를 수 없다. ClearScan 합성 글꼴처럼 이름에 정보가 없거나, 원문이 손글씨풍·장식 글꼴인 경우가 많기 때문이다. 그래서 글자 모양을 보고 고른다.

1. **글꼴 목록:** 상업적 이용·PDF 내장이 가능한 무료 한글 글꼴(SIL OFL)을 `fonts/`에 두고, `fonts/catalog.json`에 글꼴마다 계열(고딕/명조/둥근/손글씨/장식), 굵기, 폭, 라이선스를 적는다. 받는 방법은 스크립트로 남겨 다시 받을 수 있게 한다.
2. **모양 재기 (코드):** 원문 영역의 글자 마스크에서 획 두께/글자 높이 비율(굵기), 획 두께의 변화 폭(세리프·붓 느낌), 모서리 둥글기, 글자 폭, 잉크 밀도를 잰다. 후보 글꼴로 같은 크기의 한글 문장을 그려 같은 값을 재고, 가까운 순으로 줄을 세운다.
   - **크기 보정:** 같은 pt라도 글꼴마다 실제 글자 높이가 크게 다르다. 손글씨 글꼴은 고딕보다 눈에 띄게 작아 보인다. 그래서 비교와 합성 모두 pt가 아니라 **원문의 실제 글자 높이(잉크 높이)에 맞춰** 글꼴별 크기를 정하고, 글꼴마다 보정 배율을 `catalog.json`에 저장한다.
3. **보고 고르기 (모델):** 원문 영역 이미지와 상위 후보 5~6개로 그린 한글 견본을 Claude 비전에 함께 보내, 인상(손글씨 느낌, 무게감, 장르 분위기)이 가장 비슷한 3개를 이유와 함께 고르게 한다. 1단계에서는 이 판단을 사람이 대신 한다.
4. **미리보기와 확정:** 후보 3개로 실제 번역문을 카드에 합성한 비교 이미지를 보여 주고, 사용자가 고르면 영역 설정의 ‘글꼴’로 저장한다. 같은 게임의 다음 프로젝트에서는 저장된 선택을 기본값으로 쓴다.
5. **원칙:** 원문 글꼴을 흉내 내는 것보다 읽기 쉬운 것이 우선이다. 본문처럼 작은 글자(6pt 안팎)에는 획이 너무 가늘거나 장식이 많은 글꼴을 후보에서 뺀다.

**한글 넣기 직전 글꼴 고르기 (2026-11-06 구현)**

‘⑧ 한글 넣기’를 누르면 한글을 넣기 직전에 ‘한글 글꼴 고르기’ 창을 띄운다. 아래 ‘글꼴 묻는 순서’(영역 지정 직후에 묻기)는 처음 계획이고, 지금은 이 창이 그 역할을 한다.

- **고르는 단위:** 항목(영역)마다 하나를 고르고, 항목을 펼치면 카드(쪽)마다 따로 고를 수 있다(기본 ‘항목과 같음’).
- **문장마다 글꼴 (2026-11-06):** 영역 편집기의 ‘글꼴 단위’에서 영역마다 ‘한 칸 모두 같은 글꼴’(기본, 적지 않음)과 ‘문장마다 글꼴 지정’(`style.font_mode = "sentence"`)을 고른다. 태그 라벨 영역은 칸 단위만. ‘문장마다’ 영역은 글꼴 창에서 카드를 펼치면 문장 줄이 나오고 문장마다 고른다(기본 ‘카드와 같음’).
  - 문장 나누기(`typeset_layout.sentence_spans`): 마침표·물음표·느낌표·말줄임표(뒤의 닫는 따옴표·괄호까지) 다음에 빈칸·줄바꿈이 오거나 글이 끝날 때, 또는 빈 줄. 태그와 `[[아이콘]]` 안은 나누지 않는다. 줄바꿈만으로는 문장을 나누지 않는다(한 문장이 여러 줄에 걸칠 수 있다).
  - 한글 넣기 직전에 고른 문장을 내부 글꼴 태그 `<f1>…</f1>`로 감싸고(`wrap_sentence_fonts`), 줄바꿈에서는 닫았다 다시 열어 줄마다 배치하는 그림 카드에서도 짝이 맞게 한다. 글꼴 태그는 `<b>`·`<cN>`과 엇갈려도 되고, 원문과 태그 수를 비교할 때 세지 않는다. 엑셀·번역문에는 들어가지 않는다.
  - 글자 크기는 영역 글꼴 기준으로 정하므로, 글자가 작게 그려지는 글꼴(손글씨 등)을 고른 문장은 다른 문장보다 작아 보일 수 있다.
- **목록:** 추천 글꼴(최대 5개, 1순위에 ★와 이유) + 이 프로젝트에서 쓴 적이 있는 글꼴(모든 파일의 `fonts.json`과 그룹 영역 설정의 글꼴) + 이 창에서 추가한 글꼴. 맨 아래 ‘글꼴 추가…’는 PC에 설치된 글꼴 중 한글이 있고 PDF에 넣어도 되는(라이선스 fsType이 내장 금지가 아닌) `.ttf`·`.otf`·`.ttc`(글꼴 모음의 글꼴마다) 목록에서 고르거나 글꼴 파일을 직접 고른다. 글꼴 모음의 글꼴은 고를 때 그 글꼴만 `.ttf`로 꺼내 `%LOCALAPPDATA%\CardTranslater\fonts\`에 두고 쓴다(굴림·돋움·바탕 등).
- **기본 선택:** 원본과 느낌이 가장 비슷한 추천 1순위. 전에 고른 것이 있으면 그것.
- **추천 만드는 법 (`app/font_match.py`, `app/font_plan.py`):**
  1. 원본과 지운 카드를 같은 영역으로 그려 비교해, 지우기로 사라진 픽셀(= 원문 글자)만 잰다. 아이콘·그림은 지우지 않았으므로 빠진다. 영역마다 최대 3쪽.
  2. 모양 값(획 굵기/글자 높이, 획 굵기 변화, 잉크가 있는 세로줄만 센 잉크 밀도)을 원문과 후보 견본(같은 높이로 그리고 스캔처럼 번지게)에서 재어 가까운 순으로 줄 세운다.
  3. 모양 값 상위 4개 + 대표 글꼴(본고딕 보통·중간·굵게, 고딕 A1 중간, 본명조 보통·굵게)로 후보 8개를 만들어, 원문 영역 이미지와 후보 견본(그 칸의 번역문)을 Claude(Sonnet)에게 함께 보내 비슷한 3개를 이유와 함께 고르게 한다. 파일당 한 번 부른다. Claude는 먼저 원문 글씨의 계열·굵기를 적고(`original_style`, 글꼴 창에서 항목에 마우스를 올리면 보임) 같은 계열을 먼저 고른다. 원문을 고딕이라 해 놓고 명조 견본을 고르는 등 계열이 어긋난 추천은 뒤로 보낸다.
  4. Claude를 쓸 수 없거나 실패하면 모양 값 순서로만 추천하고 창 위에 알린다. 일본어 가나·영문과 한글은 모양이 달라 모양 값만으로는 명조 쪽으로 쏠리기 쉬우므로, 원문 획 굵기 변화가 아주 크지 않으면 명조를 뒤로 보내고, 손글씨·장식 글꼴도 뒤로 보낸다.
  - 추천은 `fonts.json`에 남겨 다시 열 때는 다시 묻지 않는다(지우기를 다시 하면 새로 추천).
- **저장 (`파일 폴더/fonts.json`):** `regions`(항목 기본), `cards`(쪽별로 항목 기본과 다른 것만), `sentences`(쪽 → 영역 → 문장 번호), `recommended`. 한글 넣기(`typeset_compose.run_compose`)가 쪽마다 ‘항목 기본 + 카드별’ 글꼴을 영역 서식의 글꼴보다 우선해 쓰고, 굵게(`<b>`)는 그 글꼴의 이웃 굵기 파일에서 다시 찾는다. 결과 보고서(`report.json`)의 칸마다 쓴 글꼴(`font_file`, 문장 글꼴은 `sentence_fonts`)을 적는다. 고른 글꼴 파일이 없어졌으면(지웠거나 다른 PC의 경로) 그 칸은 영역 글꼴로 넣고 상태 ‘글꼴 없음’을 남겨 결과 보기의 ‘문제 있는 쪽’에 나온다.
- 엑셀 확인 항목 때문에 ‘그래도 넣기’로 다시 부를 때는 글꼴 창을 다시 띄우지 않는다.

**글꼴 묻는 순서**

글꼴은 앱이 정해 버리지 않고 반드시 사용자에게 묻는다. 추천은 앱이 하고, 결정은 사람이 한다.

1. **언제:** 영역을 정한 직후(2단계 뒤), 지우기(7단계) 전에 묻는다. 지우기에는 글꼴이 필요 없지만, 늦게 물으면 임시 글꼴로 만든 결과를 보고 다시 고치게 된다.
2. **무엇을 묻나:** 영역마다 하나씩 차례로 묻는다. 모양이 같고 위치·회전만 다른 영역(예: 위·아래 반쪽의 같은 이름 영역)은 한 번만 묻고 함께 적용한다. 같은 게임에 저장된 선택이 있으면 그것을 기본값으로 보여 주고 바꿀지만 묻는다.
3. **보여 주는 것:**
   - 원문 영역 이미지 (기준 카드 + 글자가 가장 긴 카드)
   - 추천 후보 3개의 견본. 원문 잉크 높이에 맞춘 크기로, 번역 초안(없으면 비슷한 길이의 견본 문장)을 원문과 같은 자리에 그린다.
   - 후보마다 추천 이유 한 줄(예: “획 굵기가 가장 비슷함”, “둥근 모서리”, “작은 글자에서도 잘 읽힘”)과 1순위 표시
   - 굵기를 고를 수 있는 글꼴은 굵기 선택(예: 본고딕 Regular·Medium·Bold·Black)
   - ‘다른 글꼴 보기’: 목록 전체를 같은 방식의 견본으로
4. **고르기:** 후보 중 하나, 목록의 다른 글꼴, 또는 사용자가 넣은 글꼴 파일(OFL 등 PDF 내장이 허락된 것만)을 고른다.
5. **미리보기 → 확정:** 고른 글꼴로 테스트 카드 1~3장에 한글을 넣은 전후 비교를 보여 준다. 괜찮으면 영역 설정(`style.font`)과 게임 단위 설정에 저장하고, 고른 날짜와 ‘사용자 선택’을 함께 적는다.
6. **답하지 않으면:** 1순위 후보로 진행하되 영역 설정에 ‘임시(사용자 미확정)’로 적고, 8단계(한글 넣기) 전 확인 목록에 ‘글꼴 미확정 영역’으로 올린다.
7. **나중에 바꾸기:** 언제든 영역 설정에서 글꼴을 바꿀 수 있다. 지운 카드(`cleared/`)는 그대로 쓰고 8단계만 다시 한다.

### 5.8 자동 정렬

같은 타입의 카드라도 PDF마다 위치가 조금씩 다를 수 있다. 첫 카드(기준 카드)에 그린 영역을 다른 카드에 맞춰 옮긴다.

1. **기준점 찾기:** 카드 테두리·틀 그림처럼 모든 카드에 공통인 부분을 기준으로 삼는다. 페이지를 낮은 해상도로 그려 기준 카드와 비교하고(특징점 매칭), 이동·크기 변화만 계산한다. 회전은 작은 각도만 허용한다.
2. **영역 옮기기:** 계산한 변화만큼 모든 영역 좌표를 옮겨 그 카드에 저장한다. 원본 페이지는 바꾸지 않는다.
3. **실패 처리:** 일치 점수가 낮거나 이동량이 비정상적으로 크면 ‘정렬 확인 필요’로 표시한다. 화면에서 그 카드 위에 영역을 겹쳐 보며 화살표 키로 미세 조정할 수 있다.
4. **보조 수단:** PDF 텍스트 레이어가 있으면, 영역을 옮긴 뒤 영역 가장자리에 걸쳐 잘린 글자가 있는지 검사해 정렬 오류를 한 번 더 잡는다.

### 5.9 테스트 실행

300장을 한꺼번에 돌리기 전에, 고른 페이지만으로 전체 과정을 시험한다.

- **페이지 지정:** `1, 5, 12-14`처럼 입력하거나, ‘글자가 가장 긴 카드 3장 + 아이콘이 가장 많은 카드 2장’을 자동으로 고르는 버튼을 둔다. 어려운 카드부터 보는 것이 가장 빠르다.
- **실행 범위:** 추출 → (현재 용어집으로) 번역 → 지우기 → 합성을 끝까지 한다. 용어집이 아직 없으면 테스트 페이지의 용어만 임시로 뽑아 쓴다. 필요하면 ‘추출만’, ‘합성만(엑셀 번역 사용)’으로 일부만 돌릴 수도 있다.
- **결과:** `test_runs/<시각>/` 폴더에 따로 저장하고, 원본과 결과를 나란히 놓은 비교 이미지와 문제 목록(넘침, 글자 축소, 서식·아이콘 불일치, 정렬 확인 필요)을 보여 준다.
- **본 작업과 분리:** 테스트 결과는 프로젝트의 추출·번역 상태를 바꾸지 않는다. 다만 글자 인식·번역 결과는 캐시에 남겨 본 작업에서 다시 비용이 들지 않게 한다.
- **되돌아가기:** 테스트를 보고 영역·서식 설정을 고치면 같은 페이지로 다시 돌려 비교할 수 있다. 최근 테스트 5번을 남겨 설정별 결과를 비교한다.
- **구현 (2026-11-12):** 시험 실행 창에서 ‘앞에서부터 N장’ / ‘쪽 지정(1, 5, 12-14)’ / ‘어려운 카드 자동 고르기(글자가 가장 긴 3장 + 아이콘이 가장 많은 2장)’를 고른다. 실행마다 그룹 폴더 `test_history.json`에 남기고 최근 5번만 둔다(밀려난 기록의 시험 폴더는 데이터 폴더 `test_runs/` 안에 있을 때만 지운다). 프로젝트 화면 ‘시험 기록’에서 결과 보기·같은 카드로 다시 시험·두 시험 비교(같은 카드의 두 결과를 나란히, 문제 목록 함께). 문제 목록: 넘침·글자 축소·서식 불일치·아이콘 불일치·정렬 확인 필요. ‘용어집이 없을 때 임시 용어’, ‘추출만·합성만’ 실행은 아직 없다.

## 6. 언어와 기술 스택

### 결정: Python + PySide6 데스크톱 앱, Windows exe로 배포 (2026-11-04)

처리 엔진은 **Python**으로 만든다. 이번 앱의 어려운 부분(이미지 처리, 글자 인식, 배경 복원, PDF, 엑셀, AI 호출)에 필요한 도구가 거의 모두 Python에 가장 잘 갖춰져 있기 때문이다. 화면은 처음에 로컬 웹으로 계획했으나, **exe로 만들어 일반 프로그램처럼 쓰기 위해 PySide6로 바꿨다.** 영역 그리기·확대·끌기는 QGraphicsView가 기본으로 지원한다. 엔진은 처음부터 화면과 나눠 두었으므로(`service.py`) 그대로 쓴다.

- **배포:** PyInstaller 폴더 방식(onedir)으로 `CardTranslater.exe`와 `_internal/`(글꼴 포함)을 만든다. 파일 하나로 묶는 방식은 실행이 느리고 백신 오탐이 잦으며, PySide6(LGPL)는 폴더 방식이 깔끔하다. 크기는 약 200~350MB로 예상한다.
- **설치 파일:** Inno Setup 6으로 `CardTranslater-Setup-<버전>.exe`를 만든다(`packaging/make_installer.py`, 버전 1.0.YYYYMMDD). 관리자 권한 없이 `%LOCALAPPDATA%\Programs\CardTranslater`에 설치하고, 제거해도 데이터 폴더와 `tools/`(Node.js·Claude Code)는 남는다. 빌드할 때 `dist/CardTranslater.exe`가 실행 중이면 파일이 잠겨 빌드가 실패하므로 먼저 끈다.
- **동작 로그 (테스트 보고용):** `%LOCALAPPDATA%\CardTranslater\logs\cardtranslater.log`(2MB × 5개 돌려 씀)에 시작 정보(빌드 버전·커밋, Windows, 데이터 폴더, 엔진, Claude Code 위치), 작업 시작·끝·실패·취소와 진행 문구, `claude` 호출(명령은 줄여서, 실패 시 출력 끝부분), Claude Code 설치 단계, 사용자에게 보여 준 오류 창, 처리되지 않은 예외를 남긴다. 프로그램이 통째로 죽으면 `crash.log`에 스택이 남는다. API 키(`sk-ant-…`)는 기록 전에 가린다. 도움말 > ‘로그 묶어서 저장’은 로그와 환경 정보(`system.json`)를 zip 하나로 만들어(기본 바탕화면) 보내기 쉽게 하고, ‘로그 폴더 열기’로 폴더를 연다. 카드 이미지·원문은 넣지 않는다. 빌드할 때 `build_info.json`(버전·커밋)을 exe에 넣는다. 고칠 수 있게: 읽지 못한 카드·API 오류(상태 코드·요청 ID)·멈춘 이유, 지우기 참고(쪽 목록), 한글 넣기 문제 칸(쪽·영역·이유·글꼴)을 남기고, 경고에는 위치(프로젝트·쪽)를 붙인다. 단계별 시간: 작업마다 `[시간]` 줄(단계 안의 Claude 요청·원본 자르기·쪽별 시간 합·평균·최대·느린 쪽)을 남기고, zip에 그것만 모은 `timings.txt`를 넣는다(명령줄 `log-times`).
- **데이터 폴더:** exe로 쓸 때는 프로그램 폴더가 아니라 사용자가 고른 데이터 폴더(기본 `문서\CardTranslater`)에 `games/`·`projects/`를 둔다. 설정은 `%APPDATA%\CardTranslater\settings.json`. 개발 중에는 저장소 폴더를 쓴다.
- **로그인 (시작 화면):** 프로그램을 켜면 ‘Claude로 로그인(Claude 구독 · Claude Code)’과 ‘API 키 사용’ 중에서 고른다. Claude 쪽은 설치 여부를 보여 주고, ‘로그인 확인’(아주 짧은 Haiku 요청 한 번)과 ‘로그인 창 열기’(새 창에서 claude → /login)를 둔다. API 쪽은 키를 붙여 넣고 ‘확인하고 저장’한다. 고른 방식은 설정에 남아 다음 시작 때 기본으로 고른다. 파일 > 로그인 방식에서 언제든 바꾼다. `claude` 명령(Claude Code)은 exe에 넣지 않는다(크기 약 330MB, 배포 조건·자동 업데이트 문제). 그 PC에 Claude Code가 없으면 ‘Claude Code 설치’ 버튼이 보이고, 누르면 Node.js(없을 때만)와 Claude Code를 사용자 폴더에 설치한다(F29).
- **포기한 것:** 휴대폰 브라우저로 진행·결과 보기. 완료 알림은 Claude 쪽 알림으로 받는다.

### 화면과 엔진 나누기

화면(명령줄, PySide6)은 엔진을 직접 부르지 않고 `service`만 부른다. 화면을 바꿔도 엔진은 그대로 쓴다.

- **층 구분:** `app/` 엔진(지우기·배치·엑셀 등) → `app/service.py` 작업 흐름 → 화면(`app/cli.py`, `app/qt/`). 화면끼리는 서로 모르고 모두 `service`만 부른다. `app/qt/`가 `service` 말고 엔진 모듈을 import하지 않는지도 테스트가 검사한다.
- **엔진 규칙:** `app/`의 엔진 모듈과 `service`는 화면 라이브러리(PySide6, FastAPI 등)를 import하지 않고 print하지 않는다. 테스트(`tests/test_service.py`)가 이것을 검사한다.
- **긴 작업:** 진행률은 콜백(`ProgressEvent`: 단계, 끝난 수, 전체, 메시지, 쪽)으로 알린다. 콜백은 작업 스레드에서 불리므로 화면이 자기 스레드로 넘긴다(웹: 큐·SSE, PySide6: Signal). 취소는 `CancelToken`으로 쪽마다 확인하고, 취소하면 작업 폴더를 지우고 예전 결과(`cleared/`·`translated/`)는 그대로 둔다.
- **사용자에게 묻기:** 엑셀 확인 항목처럼 사람이 정할 일은 예외가 아니라 결과 상태(`needs_confirmation` + 목록)로 돌려준다. 화면이 물어보고 ‘계속’이면 다시 부른다. 그래서 명령줄의 `--yes`, 웹의 확인 창, PySide6의 대화상자가 같은 흐름을 쓴다.
- **화면에 넘기는 것:** 결과는 경로·상태·경고를 담은 dataclass로 준다. 이미지는 파일 경로(PNG)로 넘겨, 웹은 URL로, PySide6는 QPixmap으로 바로 읽는다.
- **좌표:** 영역은 지금처럼 카드 대비 비율로 저장한다. 명령줄로 손으로 쓴 `regions.json`과 PySide6 영역 편집기가 같은 파일을 쓴다. 편집기는 모르는 항목(메모, 태그 색 사전, 글꼴을 고른 이유 등)을 지우지 않고 그대로 둔다.

## 7. AI 모델 추천

모델은 두 곳에 쓴다. 앱이 실행 중에 부르는 모델(글자 인식·번역)과, 앱을 만들 때 Claude Code에서 쓰는 모델이다. 모델 이름은 코드에 박지 않고 `.env`에서 바꿀 수 있게 한다.

### 앱 안에서 쓰는 모델

| 작업 | 기본 추천 | 아끼고 싶을 때 | 품질이 부족할 때 |
| --- | --- | --- | --- |
| 이미지 글자 인식 | Claude Sonnet 5.5 (`claude-sonnet-5-5`) | Claude Haiku 5.5 — 글자가 크고 깔끔한 인쇄체일 때. 또는 로컬 PaddleOCR(무료) | 해상도를 높여 다시 보내기가 먼저다. 모델을 올리는 효과는 크지 않다 |
| 초벌 번역 | Claude Sonnet 5.5 | Claude Haiku 5.5 — 짧은 이름·단어 위주 카드 | Claude Opus 5.5 (`claude-opus-5-5`) — 규칙 문장이 길고 해석이 어려운 카드만 |
| 배경 복원 | OpenCV inpaint (로컬) | — | LaMa (로컬, 무료). 처음 한 번 모델 파일을 내려받는다 |

비용을 줄이는 방법:

- **같은 원문은 한 번만:** 캐시로 중복 호출을 없앤다. 카드 게임은 반복 문구가 많아 효과가 크다.
- **일괄 처리(Message Batches API):** 당장 결과가 필요 없는 대량 추출·번역은 할인된 일괄 처리로 보낼 수 있다(P1).
- **프롬프트 캐싱:** 매번 같은 용어집·지침을 앞부분에 두고 캐시해 반복 입력 비용을 줄인다.
- **작은 이미지:** 글자 인식에는 카드 전체가 아니라 영역만 잘라 보낸다.

정확한 가격과 할인 폭은 바뀔 수 있으니 만들기 전에 Claude 문서(docs.claude.com)에서 확인한다. 처음에는 카드 10장으로 시험해 장당 비용을 재고 전체로 늘린다.

### 개발할 때 (Claude Code)

| 상황 | 추천 모델 | 이유 |
| --- | --- | --- |
| 설계, 어려운 문제 해결 | Claude Opus 5.5 | 글자 마스크·배경 복원·한글 줄바꿈처럼 결과를 보고 여러 번 고쳐야 하는 이미지 처리에 강하다 |
| 화면·엑셀 입출력 등 반복 구현 | Claude Sonnet 5.5 | 빠르고 사용량 부담이 적다. 설계가 정해진 뒤의 일반적인 코드에 충분하다 |

단계를 시작할 때 `/model`로 바꾼다. 기본은 Sonnet 5.5로 두고, 5.4·5.5절(글자 지우기·한글 배치) 작업과 원인을 모르는 버그에서만 Opus 5.5로 올리는 방식을 권한다.

### 8.2 Claude Code에 만들어 둘 스킬

프로젝트의 `.claude/skills/` 폴더에 아래 스킬을 만들어 두면, Claude Code가 관련 작업을 할 때마다 같은 규칙을 따른다. 대화마다 규칙을 다시 설명하지 않아도 된다.

| 스킬 | 담을 내용 | 언제 쓰나 |
| --- | --- | --- |
| `excel-roundtrip` | 4장의 두 엑셀 형식(번역\_검수, 용어집), key 규칙, import 검사 항목, 테스트용 샘플 엑셀 | 엑셀 내보내기·가져오기를 고칠 때 |
| `glossary` | 용어 후보 뽑는 기준, 변형 처리, 게임 단위 저장 위치, 번역 뒤 용어 검사 규칙 | 용어집 만들기·검사 코드를 고칠 때 |
| `icon-handling` | 아이콘 찾기(템플릿 매칭) 기준, `[[단어]]` 이름 규칙, 보조형/대체형 판단, 조사 선택, 백업 폴더 구조, 합성 크기·위치 | 아이콘을 다루는 모든 코드 |
| `korean-typesetting` | 어절 줄바꿈, 줄 시작 금지 문자, 아이콘+조사 묶기, 크기 맞추기 알고리즘, 글꼴 설정 | 한글 배치 코드를 쓰거나 고칠 때 |
| `text-erase` | 배경색 추정, 마스크 넓히기 기준, 단색/복원 선택 기준, 실패 사례 | 글자 지우기를 개선할 때 |
| `card-translation-style` | 게임 소개, 문체 지침(규칙은 ‘\~한다’체 등), `[[단어]]` 다루는 법, 번역 프롬프트 원문 | 번역 프롬프트를 고칠 때, 게임을 바꿀 때 |
| `visual-check` | 전후 비교 이미지를 만들고 눈으로 확인하는 절차, 확인할 체크리스트 | 이미지 결과가 바뀌는 모든 작업의 마지막 |

`visual-check`가 가장 중요하다. 이미지 처리는 테스트가 통과해도 결과가 어색할 수 있어, Claude Code가 결과 이미지를 직접 열어 보고 고치게 해야 한다.

### 8.3 가져다 쓸 수 있는 것

- **Anthropic 공개 스킬:** 엑셀을 다루는 `xlsx`, PDF를 다루는 `pdf` 스킬이 공개되어 있다. Claude Code에 설치하거나 내용을 참고해 위 스킬을 만들면 된다.
- **화면 디자인:** 영역 지정 화면은 단순해도 충분하다. 따로 디자인 스킬을 쓸 필요는 크지 않다.
